# Как дотянуть «Дурак Онлайн 3D» до AAA-качества

**Дата:** 16 августа 2026  
**Объект:** `durak-online-3d` (VK Mini App 54720415)  
**Объём кода:** ~3600 строк JS, без бандлера, без БД, Three.js r128 с CDN

Это не маркетинговый бриф. Это аудит того, что уже лежит в репозитории, и честный план, без которого «AAA+++» останется надписью в `console.log`.

---

## 1. Вердикт

Сейчас это **сильный вертикальный срез** (playable prototype), а не AAA-игра.

| Слой | Оценка vs. реальный AAA-карточный продукт | Что это значит |
|---|---|---|
| Правила дурака | 7/10 | Подкидной + переводной, лимит первой биты, серверная валидация рук |
| Мультиплеер / доверие | 3/10 | Нет персистенции, VK-id можно подделать, ставки почти декоративные |
| 3D / арт | 4/10 | Есть стол и веер, но ассеты JPG отсутствуют, карты рисуются на canvas |
| Feel (звук, анимации, ввод) | 3/10 | Процедурные бипы, пересборка мешей каждый `gameState`, нет прицельного отбоя |
| Мета / удержание | 2/10 | Магазин-заглушка, экономика в `Map`, чат — toast |
| Платформа VK | 4/10 | Bridge есть, Pay/Stories не закрыты на сервере |
| Инфра / качество | 4/10 | Есть тесты потока и Puppeteer, нет CI-скриптов, нет масштабирования |

**Итоговая планка:** ~3.5/10 относительно Hearthstone / PokerStars / «Дурак Онлайн» на VK.  
Как VK Mini App-прототип: ~6/10 — уже можно тыкать, нельзя удерживать аудиторию.

«AAA+++» в индустрии не существует. Рабочая цель для этого продукта:

> **Лучший 3D-дурак во ВКонтакте:** 60 fps на среднем Android в WebView, честный стол, живые друзья, колода которую хочется фотографировать, матч за <15 секунд.**

До этой планки путь не в ещё одном PBR-шейдере, а в закрытии дыр ниже. Игроки VK уходят не потому, что сукно недостаточно бархатное, а потому что стол сбрасывается, бот тупой, а «побить» бьёт не ту карту.

## 2. Что уже не надо изобретать

Не обесценивать фундамент — он лучше, чем выглядит README.

- Серверная машина состояний: `WAITING → DEALING → ATTACKING → DEFENDING → GAME_OVER` в `server/gameEngine/DurakGame.js`.
- Режимы подкидной / переводной, 2–6 игроков, колоды 24 / 36 / 52, правило «макс. 5 в первой бите».
- Анти-чит по рукам: `getSanitizedState(forPlayerId)` отдаёт чужие карты пустым массивом.
- Серверный таймер хода 30с: авто-взять / авто-пас / автоход младшей.
- Quick match с автодобором ботов.
- Скелет VK Mini App: init, профиль, taptic, Stories/Wall, Pay-хук.
- HUD под концепт: стеклянная консоль, козырь, таймер, бейджи мест через проекцию 3D→2D.
- Тесты: `tests/test_game_flow.js`, `tests/test_turn_timer.js`, `tests/test_visual.js`.

Это **P0-ядро настолки**. AAA строится поверх него, а не вместо.

## 3. Разрыв с AAA по столпам

### 3.1 Карты — лицо продукта

Сейчас лица — `CanvasTexture` 512×716 с пипами и буквами В/Д/К. Фигуры — рамка + литера, не портрет. «Атласные» JPG (`king_hearts.jpg`, `ace_spades.jpg`) **загружаются, но файлов в репо нет**. В `client/assets/cards/` лежат только SVG-рубашки.

AAA-колода:

- Один атлас 4K (или 2 LOD: 2K мобильный / 4K десктоп) на 36/52 лица.
- Отдельные рубашки как SKU магазина, а не градиент «VIP» на canvas.
- Фольга / normal / roughness на легендарках (не обязателен PBR на каждую карту — важен блик при повороте).
- Единый язык рангов: сейчас сервер пишет `J/Q/K/A`, клиент рисует `В/Д/К/Т`. Это выглядит как баг локализации.

Бенчмарк: физическая колода Piatnik / Modiano в руке, а не «красивый CSS».

### 3.2 Стол и комната

Код грузит:

- `assets/table/casino_bg_portrait.jpg`
- `assets/table/felt_emerald_pure.jpg`
- `assets/table/casino_room_pano.jpg`
- `assets/table/mahogany_rim.jpg`

На диске: `felt_emerald.svg`, `room_panorama.svg`. JPG нет. Three.js молча рисует чёрный/белый меш — «AAA-графика» в коммитах не воспроизводится из репозитория.

Камера в `updateCameraForPlayerCount` **игнорирует `count`**: всегда `y=4.8, z=6.2`. Комментарий про адаптив на 2–6 игроков — ложный.

Скины стола: `setTableColor` пишет в `this.feltMat`, который нигде не присваивается. Смена сукна в магазине не работает.

AAA-стол:

- Одна HDRI-комната (не plane 18×14 с JPG).
- Сукно = tiled albedo + roughness + faint normal (ворс).
- Камера-риг: portrait / landscape / 2p / 6p как отдельные пресеты, не одна точка.
- Quality scaler: shadows 512 на слабых VK Android, 2048 на десктопе.

### 3.3 Feel (то, за что платят «ААА»)

| Сейчас | Нужно |
|---|---|
| Процедурный white-noise «шелест» | 8–12 записанных фоли: слайд, хлопок, снятие колоды, бита, фишки |
| Каждый `gameState` уничтожает и создаёт чужие карты | Пул мешей + tween только дельты |
| Отбой всегда в первую незакрытую пару | Drag на конкретную атакующую карту + подсветка легальных |
| Кнопка «Побить» = toast «нажмите на карту» | Режим выбора цели, как в Hearthstone |
| Предметы = сфера/цилиндр | 5 GLB-пропов с splat-декалями |
| Чат = toast с тремя фразами | 8 быстрых реплик + эмодзи над местом, без клавиатуры |
| Победа: `streak: 5` захардкожен в шаринге | Реальные `winStreak` / время матча с сервера |
| Ставки не списываются | Escrow фишек на старте, settle на `GAME_OVER` |

Без этого стол выглядит «дорого» одну секунду и ощущается прототипом на втором ходе.

### 3.4 Доверие и экономика

`EconomyService` — `Map` в памяти процесса. Рестарт Railway = все фишки 5000, все скины сброшены.

Авторизация:

```js
id: playerData.id || 'vk_' + socket.id.substring(0, 6)
```

Любой клиент шлёт чужой `vk_123` и играет чужим профилем.

VK Pay:

```js
await vk.openVKPay(...)
this.userEconomy.chips += pack.chips  // клиент сам себе начисляет
```

Серверный `/api/vkpay/order` не проверяет подпись уведомления VK.

Это не «потом допилим монетизацию». Это блокер релиза: магазин, daily, ставки — игрушки, пока нет:

1. Проверки `vk_user_id` из launch params / `sign`.
2. Postgres (или хотя бы Redis) для баланса.
3. Callback VK Pay с проверкой подписи.
4. Идемпотентных ордеров.

### 3.5 Правила и ИИ — дыры, которые бьют «честность стола»

В `attack()` нет проверки «первый ход делает только текущий атакующий». Любой не-защитник может выложить первую карту. Для подкида после появления карт на столе это частично ок, для открытия круга — нет.

Бот: младшая некозырная. Нет учёта «не бить козырем в первой бите», «не подкидывать в длинную руку», «перевод только если следующий слаб». Игрок за 3 партии понимает паттерн и бросает PvE.

Нет: реконнекта (disconnect → мгновенный бот), паузы «связь потеряна 45с», доигрыша зрителем, рейтинга, «честной колоды» с аудитом seed (для турниров).

### 3.6 Платформа и техника

- Three.js **r128 (2021)** с cdnjs + GSAP + vk-bridge с unpkg. В VK WebView CDN = белый экран при блокировке.
- Нет Vite/ESBuild: ES-модули с диска, без tree-shake, без gzip-контроля.
- `renderer.setPixelRatio(min(dpr, 2))` + shadow 2048 на всех. На Redmi в VK это 15–25 fps.
- `renderPlayerSeats` делает `innerHTML = ''` каждый стейт + `requestAnimationFrame` на проекцию бейджей. Лишняя работа и мерцание аватарок.
- Нет `npm test` в `package.json`. Тесты есть, в CI их никто не гоняет из скриптов.
- Один Node-процесс, комнаты в RAM, `cors: origin: '*'`. Горизонтали нет.

## 4. Что считать AAA именно для дурака во VK

Не копировать Unreal-казино. Бюджет кадра и канал VK WebView жёстче, чем у нативного клиента.

**Must-have ощущения (игроки это называют «дорого»):**

1. Карта в руке читается с 30 см, фигуры — иллюстрации, не буквы.
2. Легальные ходы подсвечены до касания. Нелегальная карта не улетает в toast-ошибку, а пружинит назад.
3. Отбой — жест «карта на карту», не «нажать ПОБИТЬ».
4. Бита / взятие — 0.8–1.2 с постановки, не телепорт.
5. Свой ход понятен без чтения промпта: светится место, вибрирует, тикает последние 5с.
6. Матч находится <15 с. Если людей нет — бот с 3 уровнями, не клон «кладу шестёрку».
7. Вышел из VK и вернулся — сел на то же место, карты на месте.
8. Фишки после победы появляются у всех одинаково и не откатываются после деплоя.

**Не must-have (часто маскируют дыры):**

- Ещё один шейдер люстры.
- Помидор / шампанское до того, как работает отбой.
- «Киберпанк-колода» текстом `CYBER DURAK` на canvas.
- Четыре кнопки консоли, если три из них disabled и дублируют жест.

## 5. Дорожная карта

Оценка трудозатрат — в объёме работ, не в календарных неделях. Каждый этап самодостаточен: после него продукт можно отдавать в VK, не обещая следующий.

### Этап A — Честный стол (блокер релиза)

Цель: игра переживает рестарт сервера и не раздаёт фишки с клиента.

1. **Авторизация VK:** проверять `sign` launch params на сокете `auth`. Гостей — только вне VK, с явным флагом.
2. **Персист:** Postgres (игроки, инвентарь, ордера) + Redis (комнаты/presence). Минимальная схема: `users`, `inventory`, `matches`, `payments`.
3. **Эскроу ставки:** списание `bet` при `start()`, выплата на `GAME_OVER`. Сейчас `vic-reward` считается на клиенте и никуда не пишется.
4. **VK Pay:** только серверный callback + проверка подписи. Удалить `this.userEconomy.chips += pack.chips` из `app.js`.
5. **Реконнект:** `socketId` отделён от `playerId`; 45с hold, затем бот; возврат — замена бота обратно на человека.
6. **Правила:** первая карта круга — только `attackerId`; подкид — остальные кроме защитника; перевод — как сейчас, плюс тест-кейсы.
7. **Ассеты:** либо положить реальные JPG/WebP, либо убрать загрузку призраков и оставить SVG/procedural с явным fallback, чтобы сцена не была чёрной.

Критерий готовности: деплой Railway не обнуляет баланс; повторный вход в комнату восстанавливает руку; Pay нельзя накрутить из DevTools.

### Этап B — Feel матча (то, что снимают на сторис)

1. **Карточный пайплайн:** атлас лиц + 2–4 рубашки как текстуры. Генератор canvas оставить fallback.
2. **Animation director:** события `cardDealt | cardPlayed | beaten | taken | bita` с сервера (уже почти есть `history`) → клиент не рендерит весь стол с нуля, а играет клип.
3. **Ввод:** drag-and-drop на конкретную пару; hover/touch lift; подсветка `canBeat` / `canToss`. Кнопка «Побить» входит в режим таргетинга, а не в toast.
4. **Камера:** пресеты 2/3/4/5/6 и portrait/landscape. Починить `updateCameraForPlayerCount`.
5. **Аудио:** 10 коротких `.m4a` (карточки <80 КБ каждая) + mixer (SFX / UI). Процедур оставить как fallback для iOS autoplay.
6. **Перф:** quality tiers `low/mid/high` (pixelRatio 1/1.5/2, shadows off/1024/2048, particles 0/12/25). Детект по `renderer.capabilities` и FPS за первые 3с.
7. **Починить скины стола:** `this.feltMat = topMat`.

Критерий: 60 fps на iPhone SE-классе в VK; отбой пальцем на нужную карту; бита выглядит как сбор колоды.

### Этап C — Продукт, из-за которого возвращаются

1. **Рейтинг:** отдельная очередь ranked 36 / подкидной 2p и 4p. MMR скрытый, визуал — лиги (дерево → бронза → …).
2. **Боты 3 уровня:** beginner (как сейчас), standard (не рвать козыря зря, не подкидывать в 6 карт), expert (учёт оставшихся мастей, перевод в слабого).
3. **Друзья VK:** `VKWebAppGetFriends` + инвайт в стол. Без этого мультиплеер = боты.
4. **Быстрый чат:** 8 фраз + 6 эмодзи, кулдаун 2с, рендер над бейджем. Кнопка 💬 уже есть.
5. **Онбординг 90 секунд:** «бей старше / козырь кроет / подкид того же достоинства / перевод». Первый бой с ботом, который играет «в камеру».
6. **Live-ops лёгкий:** ежедневка с серией 7 дней (сейчас фиксированные 1500/10), квест «3 победы переводным».
7. **Шаринг правды:** сторис берёт `winners`, `durak`, `bet`, `duration` с сервера, не литералы `5` и `03:45`.

Критерий: D1 retention измеряется; человек может вызвать друга из VK; новичок понимает перевод без статьи.

### Этап D — Масштаб и «премиум»

1. Бандл: Vite, Three r16x как npm, никакого unpkg в проде.
2. Socket.IO Redis adapter, несколько инстансов Railway.
3. Наблюдатели стола, турнир на 8/32, сезонная колода.
4. Анти-чит глубже: rate-limit ходов, seed колоды на сервере (уже так), лог матча для споров.
5. Аналитика: воронка лобби → матч → победа → шаринг; FPS; crash VK WebView.
6. Юридическое: оферта, 18+, правила фишек как «без вывода в рубли» — иначе VK режет.

Это уже не «дотянуть графику», это операционка живого приложения.

## 6. Конкретные дыры в текущем коде (быстрые победы)

Их можно закрыть до любой «графики». Они сильнее влияют на ощущение качества, чем люстра.

| Проблема | Где | Эффект |
|---|---|---|
| JPG сцены не в репо | `scene3d.js`, `cards.js`, `main.css` | Чёрный стол / сломанные рубашки |
| `feltMat` не задан | `scene3d.js` `setTableColor` | Магазин столов мёртв |
| Камера не зависит от числа игроков | `updateCameraForPlayerCount` | 6 человек в кашу, 2 — пустота |
| Первая атака не привязана к `attackerId` | `DurakGame.attack` | Рассинхрон «чей ход» |
| Чужие руки destroy/create каждый стейт | `cardRenderer3d.renderOpponentsHands` | Мигание, GC, нет анимации добора |
| Места HUD через `innerHTML = ''` | `app.js` `renderPlayerSeats` | Мигание аватарок |
| Начисление VK Pay на клиенте | `app.js` `renderShopTab('currency')` | Бесплатные фишки |
| Экономика в RAM | `economyService.js` | Обнуление после деплоя |
| Чат-заглушка | `btn-chat-toggle` | Мёртвая кнопка в «премиум»-консоли |
| Шаринг с фейковыми статами | `storyShare` / `btn-share-vk-story` | Сторис врут — игроки это видят |
| Ранги J vs В | `Deck.js` vs `cards.js` | Карта на сервере и на столе «разные» |
| Нет `npm test` | `package.json` | Регрессии правил не ловятся |
| CDN three/gsap/bridge | `index.html` | Белый экран в WebView без CDN |

Приоритет внутри этапа A: авторизация → персист → эскроу → реконнект → правило первой атаки → ассеты/фолбэки.

## 7. Чего не делать

- Не писать в README/логах «AAA+++» пока нет персистенции и живых ассетов. Это снижает доверие к остальным обещаниям (анти-чит, VK Pay, бархат).
- Не добавлять новые throwable / скины / люстры, пока отбой не работает жестом на конкретную карту.
- Не тащить Unreal/Unity «потому что AAA». Канал — VK Mini App. Выигрывает WebGL-бюджет и холодный старт <3 с, не Nanite.
- Не делать вывод фишек в рубли. Для VK это казино-серая зона; модель — косметика + мягкая валюта без cash-out.
- Не усложнять движок дурака редкими вариантами (с козырным валетом, «че dumak») до стабильного классического подкидного 36.

## 8. Метрики, по которым видно, что планка взята

Пока этих цифр нет — «графика как в концепте» не считается.

| Метрика | Прототип сейчас | Цель «лучший дурак в VK» |
|---|---|---|
| Холодный старт до лобби | CDN + шрифты Google, не измерено | < 3 с на 4G |
| FPS матча (Android mid, VK) | неизвестно, shadows 2048 | p50 ≥ 55, p95 ≥ 30 |
| Время до первого хода | quick match + 3 бота ~2 с | < 15 с в PvP-очереди, < 5 с vs бот |
| Реконнект в тот же стол | нет | ≥ 95% успешных возвратов < 45 с |
| Баланс после деплоя | 0% сохранён | 100% |
| Ошибки «карта не бьёт» / неверный подкид | через toast | < 2% ходов (UI должен не давать слать мусор) |
| Шаринг сторис | кнопка есть, статы фейк | ≥ 15% победителей жмут share |
| D1 / D7 | нет аналитики | измеряется; ориентир D1 ≥ 25% для казуала VK |

## 9. Рекомендуемый порядок работ в репозитории

Если делать руками в этом коде, а не переписывать с нуля:

```
A1  VK sign + user id канонический
A2  Postgres users/inventory/matches
A3  Settle ставки на GAME_OVER
A4  Reconnect token + hold
A5  Фикс attack() первой карты + тесты правил
A6  Реальные WebP ассеты ИЛИ жёсткий fallback без 404
B1  Пул карт + event-анимации
B2  Drag на пару + подсветка легальных
B3  Камера-пресеты + quality tier
B4  Фонотека m4a
C1  Быстрый чат + VK invite
C2  3 уровня ботов
C3  Ranked 1v1 36 карт
```

Переписывать клиент на TypeScript/Vite имеет смысл **на стыке A→B**, когда протокол стейта стабилен. Переписывать `DurakGame.js` рано: его надо покрыть юнит-тестами правил и чинить, а не менять язык.

## 10. Одна фраза

**До «AAA» отсюда не шлифуют люстру — закрывают доверие (аккаунт, деньги, реконнект), затем feel карт (атлас, жест отбоя, дельты анимаций), затем мета VK (друзья, рейтинг, честный шаринг).** Графика без этих трёх слоёв останется концепт-артом в коммите.
